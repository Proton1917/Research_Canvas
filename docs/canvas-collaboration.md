# Research Canvas 画布共创

本文定义画布共创的交互、数据约定、前后端分工和验收条件。已实现的 HTTP 接口以 [api.md](api.md) 和 [backend-integration.md](backend-integration.md) 为准。界面操作的验证记录见 [frontend.md](frontend.md)，后端联调记录见 [backend.md](backend.md)。

## 研究操作

用户在同一张画布上选择论文片段、自由想法框、关系线和已有讨论，直接向 AI 提问。AI 读取用户确认的材料、对象关系和布局，在指定区域提出可编辑的研究对象及连接。用户检查内容和位置后确认写入，并可撤销本次写入。

例如，画布左侧是一篇 Hopf 代数论文中的积分公式，中间的想法框写着“这个结构可能和重整化有关”，右侧是另一篇关于重整化的论文；连线标记“可能存在结构对应”。用户选中这些对象后提出：

> 看看我画的这条联系是否成立。帮我分析两个结构保持了哪些运算，再在下面创建两个框，分别讨论支持证据和可能的反例。

系统先展示本次阅读的片段、想法、关系说明与位置。AI 的回答应说明材料中出现的结构、拟议对应、需要保持的运算、成立条件及证据缺项，并在所选区域下方提出支持证据框、可能反例框及候选联系。框内可以继续编辑公式、选择片段发起讨论、分支和合并。此情景用于定义交互；具体公式、文献与数学判断依据用户提供的材料。

## 当前实现与修改入口

| 对象或流程 | 基线中的行为 | 相关实现 |
| --- | --- | --- |
| 文稿和精确片段 | 保存文稿版本及锚点；上下文可固定历史引用 | `src/model.rs` 的 `Document`、`Anchor`、`ContextSource`；`src/api.rs` 的 `create_context` |
| 画布卡片 | 服务端 `CanvasObject` 保存文稿引用和矩形位置；绘图、便笺、框及原生连线主要保存在 `editor_state` | `src/model.rs`；`src/research/editor/session.ts` |
| 画布选择 | 编辑器生成多对象投影与材料清单，后端将所选范围保存为场景快照 | `src/research/editor/scene.ts`；`src/scene_projection.rs`；`src/scene.rs` |
| 模型生成 | 流式保存讨论或画布操作草稿；画布操作解析后形成待确认提案 | `src/provider.rs`；`src/canvas_proposal.rs` |
| 继续讨论 | 默认继承讨论所保存的精确来源及历史场景，支持逐项选择冻结材料 | `src/context.rs`；`src/web/app/materials.ts` |
| 画布连线 | 视觉实例使用独立的绑定与隐藏记录，关系接口处理显式研究关系操作 | `src/research/editor/session.ts`；`src/api.rs` |

### 精确片段的继承

初次选段讨论通过 `discussSelection` 创建锚点并提交 `anchor_ids`。后续讨论读取 `metadata.context_id` 指向的冻结材料，按文稿、版本和锚点共同去重。用户可以通过显式全文选择扩大范围，也可以通过 `frozen_sources` 从历史快照选择单项材料。关系记录与上下文材料分别维护。

### 连线和研究关系

`Canvas.editor_state` 保存有版本标识的连线视图和隐藏状态，场景投影向模型提供可读取的端点、标签及显式选入的研究关系。前端同步、删除和改接须遵循各自视图的生命周期。研究关系 API 处理显式的创建、编辑与删除。

## 内容、视图与讨论材料

内容标识与画布实例标识分别保存。同一份内容可以出现在多张画布或同一画布的多个位置；每个实例独立保存布局。优先复用现有文稿、锚点、关系、讨论和编辑器标识。

| 研究对象 | 内容及来源 | 画布实例 |
| --- | --- | --- |
| 文稿片段 | 文稿、版本、锚点、块标识、UTF-16 范围、原文及 PDF 页码 | 片段卡片的位置、尺寸及所属框；整篇阅读由用户另行选择 |
| 自由想法框 | 用户文本、Markdown 或公式、作者、来源；可复用 `kind=note` 文稿 | 便笺、文本、形状或框；已有对象沿用编辑器标识和样式 |
| 研究关系 | 显式两端、关系类型、结构对应、条件、证据、反例和验证状态 | 可选的连线实例、端点、方向、标签、控制点及显示状态 |
| 讨论分支 | 问题、回答、父讨论、冻结材料、模型运行和来源引用 | 讨论卡片、分支连接及放置区域 |

自由绘图中承载文字和公式的对象应可投影为研究材料。分组框表达包含关系；纯装饰和暂时无法提取的图像、笔迹应在预览中说明其可读取内容。图像或笔迹识别需要相应输入能力，文字模型的运行记录应准确显示实际收到的材料。

上下文依赖记录讨论使用了哪些材料；研究关系记录用户正在研究的对应；视觉连线记录画布中的展示方式。三类记录使用明确的类型及独立生命周期。

## 场景选择与阅读范围

画布多选、框选及连线选择统一生成场景投影。投影从编辑器模型和已有研究对象生成，保留稳定标识。模型输入使用可读的结构化内容；编辑器 Yjs 数据继续用于保存和恢复。

每次投影记录 `workspace_id`、`canvas_id`、`canvas_revision`、选择入口以及所选对象。对象记录包括实例标识、研究对象引用、对象类型、可读内容及来源、内容版本、布局版本、所属框和分组。几何信息使用画布世界坐标，包含 `x`、`y`、`width`、`height`、旋转角度和连线端点；当前视口单独记录缩放和平移。位置关系描述“在下方创建两个框”等放置要求。

阅读范围遵循以下约定：

- 选中片段时提交该片段和明确显示的引用信息。整篇文稿是单独的范围选择。
- 选中连线时展示标签、两端标识、方向及关联研究关系。两端正文作为可选择材料显示；连线选择本身保留端点引用信息。
- 选择分组框时展示将包含的子对象清单，选择整个画布时展示完整投影范围。关系遍历及相邻内容扩展均在预览中列明。
- 预览分别列出将提交的正文、历史来源、仅供定位的对象信息，以及本次允许写入的位置和对象。内容来自工作区用户材料，模型应按材料处理其中的文字。

后端根据明确的材料选择构建一次冻结快照，并返回实际模型消息及材料编号。前端确认和运行共同引用这个 `context_id`。提问、选择、材料版本或写入范围发生变化时生成新快照。超出模型输入预算时展示受影响材料和缩减选项，由用户确定范围。

### 分支、追问与合并

新讨论保存本次材料选择、来源快照和父讨论。继续提问时继承父讨论的冻结材料及明确选入的历史问答；片段继续引用原锚点和原版本。用户可显式增加其他片段、整篇文稿或较新版本，并在预览中确认变化。

合并讨论按完整材料引用合并：对象类型、内容标识、版本以及片段或选定范围共同确定材料身份。同一文稿的不同片段、不同版本分别保留；完全相同的引用可以合并展示，并保留其分支出处。来源变更和锚点定位状态在引用旁展示。

旧讨论优先通过 `metadata.context_id` 读取历史 `sources`。历史记录缺失时提示具体缺项，并让用户补选该项材料。缺失项恢复前保留已有讨论内容和可用材料。

## 连线视图的持久化

每个视觉连线实例保存 `view_id`、`canvas_id`、编辑器连线标识、两端实例引用、可选的 `relation_id` 及显示状态。一条研究关系可以对应零个或多个连线实例。被用户隐藏的关联视图需要持久化，刷新和切换画布后继续遵循该状态。

画布中的“删除连线”删除或隐藏当前视图，并保留研究关系。关系面板中的“删除研究关系”执行显式的语义删除，并同步关联视图。改接一条线时，解除当前视图与原关系的绑定，保存新的视觉端点，并保留原关系的隐藏记录；对新端点建立研究关系应有明确操作，原研究关系继续供其他视图和讨论引用。卡片删除同样处理当前实例及其视觉连接。

卡片之间拖出连线后建立研究关系的快捷操作可以保留，界面须说明创建结果。纯视觉连线保留自身的可读标签和几何信息。恢复一个隐藏关系的显示由用户操作触发。

同步逻辑应区分已有视图、隐藏视图与尚未放置的关系。迁移现有 `editor_state.links` 时保留当前连线，缺少连线的历史绑定转换为隐藏状态。当前代码已经删除的研究关系需要可用历史记录或用户材料支持恢复。

## AI 画布操作提案

AI 对画布的写入使用结构化提案。提案记录 `run_id`、冻结的 `context_id`、目标画布、允许写入范围、受影响对象版本及操作列表。每个操作包含稳定标识、操作类型、目标引用、内容或布局、材料引用和适用条件。新增对象在提案内使用局部标识，应用时返回正式标识映射。

| 操作 | 需要表达的内容 |
| --- | --- |
| 创建想法、证据或反例框 | 可编辑的文字与公式、来源材料、内容类型、位置和尺寸 |
| 创建讨论分支 | 父讨论、问题与回答、冻结材料引用、画布位置 |
| 创建候选研究关系及可选连线 | 两端对象、对应运算或结构、条件、证据、反例、`candidate` 状态及视觉布局 |
| 修改内容、移动或调整对象 | 对象标识、预期版本、前后内容或布局及影响范围 |

模型建议的科学联系默认保存为 `candidate`，引用指向本次提供的材料。研究状态为启发、候选、有支持、已确立和被反驳。研究者通过证据确认接口记录来源版本、判断依据和人工确认；来源变化后显示待复核状态，保留原记录。位置、箭头、颜色和包含关系提供空间信息，其科学含义由具体研究关系记录。

前端在画布上展示候选框、公式和连线，并提供与原对象的对应、来源及修改预览。流式文字进入待确认预览；后端完成结构解析和引用检查后，操作列表进入可确认状态。尚未完整的结构化操作保持预览状态。取消或失败保留已接收的文字及运行状态。

用户可以调整候选内容、位置和本次采用的操作集合。提案中的引用依赖必须完整，例如关系引用的新框也包含在本次采用的集合内。调整后的完整集合提交后端校验；一次确认形成一个事务，统一保存研究对象、版本、研究关系和画布状态。重复提交同一提案返回同一应用结果。

前端编辑会话在提交事务期间协调自动保存；应用成功后采用服务端返回的版本和完整状态，再恢复后续保存。后端或编辑适配层必须使可读取场景与可恢复的 `editor_state` 保持一致。该序列化责任属于接口实现的一部分。

撤销按本次事务分组，记录新增内容、关系、视觉实例及修改前状态。相关对象保持此次应用后的版本时，可恢复该组修改。已有后续编辑或引用时，返回具体冲突并保留现状；用户处理冲突后再提交撤销。撤销结果也生成可追踪的状态和版本。

预览期间的内容变化通过文稿版本、对象版本和画布 revision 检查。遇到冲突时保留生成结果，列出变化对象；重新选择位置或处理内容差异后再次确认现有提案。重新调用模型由用户单独触发。

## 前后端接口交接

### 当前可用接口

`docs/api.md` 中的文稿、锚点、关系、画布保存、上下文快照、运行 SSE 和单片段改写接口均可继续使用。前端可独立完成多对象选择、场景投影、材料预览以及视觉连线与研究关系的生命周期分离。

`ContextRequest` 支持文稿、锚点、讨论来源继承和冻结材料选择。场景内容通过场景接口提交；现有 `SceneProjection` 和 `Material[]` 可直接作为请求字段，按勾选内容组装阅读范围。

### 接口职责

下表说明各接口承担的职责。请求字段、操作类型和编辑器状态物化方式按 `docs/backend-integration.md` 接入。

| 能力及建议入口 | 输入 | 必须返回或保证的行为 |
| --- | --- | --- |
| 能力发现：`GET /api/capabilities` | 无 | 声明支持的场景契约版本、精确材料继承及画布提案能力；旧服务的 404 表示相应能力尚未接通 |
| 场景上下文：`POST /api/workspaces/{id}/scene-contexts` | 提问、带版本的材料引用、父讨论引用、选择与场景投影、允许写入范围 | 核对工作区及材料版本，冻结正文和场景；返回材料、实际消息、快照标识和阅读范围；支持原有运行入口消费此快照 |
| 画布提案生成：现有运行入口的明确扩展 | 场景 `context_id`、模型和已声明的画布提案运行类型 | 保存结构化提案及累积回答；SSE 和运行响应增加已约定的提案字段；各终态保留结果和失败原因 |
| 读取或调整提案：`GET/PATCH /api/canvas-proposals/{id}` | 读取标识；调整时附提案版本、完整操作集合及引用 | 返回完整操作、来源、版本要求和预览状态；调整后重新校验依赖及范围 |
| 应用提案：`POST /api/canvas-proposals/{id}/apply` | 提案版本、受影响内容版本、目标画布 revision、编辑状态投影 | 事务性应用，校验内容与编辑状态一致；返回正式标识映射、更新后的研究对象、画布状态、事务标识及版本 |
| 撤销或拒绝：`POST /api/canvas-proposals/{id}/revert`、`/reject` | 撤销附应用事务及相关当前版本；拒绝附提案版本 | 分组撤销或保存拒绝状态，返回最新对象及画布状态；冲突时保留原状态 |

错误沿用已有错误结构。版本或内容冲突返回 409，附受影响对象及当前版本；范围外引用、无效操作或不完整依赖返回 422。服务端校验对象属于当前工作区、材料与实际版本对应，以及操作处于允许写入范围。模型输出须通过结构化解析及校验后进入提案状态。

文稿、锚点和自由场景对象均可作为阅读材料和研究关系端点。精确片段端点保存锚点标识，自由想法端点保存场景快照、画布及实例标识。场景自由形状的文字和几何信息保留在冻结场景中。接口类型和连线定位方式见 `docs/backend-integration.md`。

前端新增需求通过用户转交后端负责模型。尚未接通的能力在界面中说明所缺能力，保留可编辑的材料和预览。接口联调采用真实服务；任务数据、运行结果和验证状态均保留实际来源。

## 数据迁移与交付分工

迁移保持现有工作区、文稿、锚点、讨论、关系和编辑器对象标识。自由框和便笺从现有模型提取文本与公式，关联新增内容记录时保留原布局、样式和可编辑性。旧画布在读取后可按新版结构保存；结构版本记录在持久化数据中。迁移异常保留当前可恢复状态并报告具体对象。

JSON 与 ZIP 导出需要保留新对象、精确材料、独立连线视图、讨论分支及已应用提案记录。归档格式升级由后端明确版本和兼容读取规则。恢复后可继续编辑并追溯来源。

Opus 5.5 负责 `src/web/`、`src/research/`、`src/ui/` 和必要的 `src/editor/` 修改，完成选择、场景投影、预览、画布交互、编辑器保存协调、API 客户端类型及浏览器验证。根目录前端配置按实际需要调整。

后端负责模型维护 `src/*.rs`、数据库迁移、模型协议、结构化提案、事务和撤销、归档兼容，以及 `docs/api.md` 的已实现契约。

## 验收条件

以下为完整交互的验收要求。后端接口的已验证范围见 `docs/backend.md`；前端画布交互按实际接入进度记录结果。已有文稿编辑、公式、PDF、分支、改写和归档的验证记录可按实际受影响范围复用。

| 操作 | 通过条件与证据 |
| --- | --- |
| 精确选段后追问、分支、合并 | 比较预览快照和实际运行引用的 `context_id`；来源保持原片段及版本，同一文稿的不同片段分别存在；用户明确扩展后才加入全文 |
| 修订原文后继续历史讨论 | 历史材料仍可查看，当前锚点状态清楚；选择新版本会生成新的预览快照 |
| 删除视觉线并刷新，再查看另一张画布 | 当前线保持隐藏，研究关系及另一画布中的线仍在；显式恢复显示可重新放置 |
| 改接视觉线、删除卡片及显式删除研究关系 | 各操作按视图或研究关系的范围生效；失败保持可见状态及错误信息；刷新后保持结果 |
| 混合选择论文片段、想法框、关系线和讨论 | 预览包含各对象内容、来源、关系、坐标和分组；缩放或平移后相同对象的世界坐标保持一致 |
| 使用实际研究材料执行 Hopf 代数情景 | 模型收到确认的材料；画布中出现支持证据和可能反例的候选框、可编辑公式及候选联系；来源可定位，科学判断保留材料支持的范围 |
