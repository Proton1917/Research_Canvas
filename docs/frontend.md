# Research Canvas 前端

前端是一个 React 19 单页应用，文稿和画布共用 `src/editor/` 中的编辑能力。所有数据来自 Rust 服务的 `/api` 接口，调用约定见 [api.md](api.md)。界面流程与实测截图见 [design/flow/index.html](design/flow/index.html)。

## 启动

在项目根目录执行（脚本加载 `scripts/environment.sh` 中的项目内 Node 22.23.4 与 Yarn 4.7.0）：

```bash
bash scripts/web.sh install     # 按 yarn.lock 安装依赖
bash scripts/backend.sh start   # 后端，默认 127.0.0.1:8787
bash scripts/web.sh dev         # 开发服务 http://127.0.0.1:5173，/api 代理到后端
```

Vite 开发代理从 `config/server.toml`（缺失时用 `config/server.example.toml`）读取后端地址；环境变量 `RESEARCH_CANVAS_API` 可改为其他地址。

| 命令 | 作用 |
| --- | --- |
| `bash scripts/web.sh typecheck` | `tsc --noEmit`，覆盖 `src/` 下全部 TypeScript |
| `bash scripts/web.sh build` | 类型检查后构建到 `dist/`；后端按 `frontend_directory = "dist"` 直接托管，访问 `http://127.0.0.1:8787/` |
| `bash scripts/web.sh preview` | 在 5173 预览 `dist/` |

模块别名以 `tsconfig.json` 的 `paths` 为唯一来源（`@editor/*`、`@research`、`@research/editor`、`@ui`），`vite.config.ts` 读取同一份配置。Vite 缓存位于 `.runtime/vite-cache/`。

## 数据约定

- **文稿保存**：每次保存同时提交文本块投影、Markdown 与 `editor_state`（`blocksuite-yjs-v1`，Y.Doc 更新的 Base64）。编辑后约 1.2 秒自动保存，页面隐藏时立即保存。版本冲突（409）时保留本地内容，用户可选择保留本地或载入服务器版本。
- **文本块投影**：块标识沿用编辑器块标识。标题、引用、列表、代码、公式块写成 Markdown 前缀，行内公式写成 `$…$`，表格写成 GFM 表格。投影可逆：服务端改写清除 `editor_state` 后，前端按文本块重建结构。投影规则新增块类型后，已保存文稿首次打开时自动补存一次文本块，编辑状态保持不变。
- **锚点**：选段按块内投影文本的 UTF-16 偏移记录，并附带文稿版本。原文修订后由后端返回原位、已重定位、原文已改、定位失效或多处匹配。
- **保存一致性**：文稿与画布各自维护编辑序号 `seq` 与已确认序号 `savedSeq`。保存在第一次等待前同步取快照，保存期间的新编辑在完成后按序号补存。切换工作区、发起场景上下文和应用画布提案前执行 `flushAll`/`flushCanvas`；仍有未保存或失败的条目时弹出确认框，列出条目与错误，由用户选择重试或放弃。AI 画布提案新建的文稿首次打开时只做 Markdown 结构转换，不立即写回；首次编辑、创建批注或发起上下文时再保存，因此未改动的候选文稿可整组撤销。
- **画布**：卡片是 `affine:embed-synced-doc`，引用统一文稿；同一文稿可出现在多张画布。`editor_state` 使用 `view_version: 2`：
  - `link_views`：连线标识 → `{relation_id, source_instance, target_instance, detached_from}`。
  - `hidden_relations`：本画布隐藏的研究关系。
  - `fragments`：片段卡片 → 锚点及版本。
  - 旧版 `links` 读取时迁移。

  视觉连线与研究关系分开保存，规则如下：
  - 删除连线只隐藏本画布的显示，研究关系保留，刷新和切换工作区后不重新生成。
  - “在本画布显示”只在移除了隐藏记录或连线视图实际变化时写入画布布局。两端未都放置时不写入，并逐端说明原因，如“属于画布「主画布」”或“尚无片段卡片在本画布”。
  - 改接端点解除绑定并记录 `detached_from`。
  - 新画的文稿间连线建立关系；未绑定的连线可用“研究这个联系”建立关系。
  - 关系的语义端点与连线的视觉端点分别保存：关系记录 `source_ref`/`target_ref`，`link_views` 记录两端画布实例。
  - 研究关系只通过显式“删除研究关系”删除，删除后各画布移除对应连线。
- **场景上下文**：多选卡片、片段、想法、连线和讨论后，用 `projectScene` 生成世界坐标、视口、框内成员、连线端点、公式及版本，再与材料清单（正文/历史/定位，`include` 决定阅读范围）一起提交 `POST /workspaces/{id}/scene-contexts`。提交前先保存画布并在对应 `canvas_revision` 重新投影。“在画布上创建”使用 `mode=canvas`，并附写入区 `write_scope.bounds`；预览与发送使用同一冻结上下文。
- **画布提案**：运行完成后读取 `run.canvas_proposal_id` 和完整提案。候选框与候选连线显示在冻结的写入区内，可调整位置、标题和正文，也可排除单项。调整后通过 `PATCH` 提交，冲突时以 `expected_canvas_revision` 重定基准。确认写入的步骤：
  1. 暂停画布自动保存。
  2. 在隔离的 Y 文档副本中按 `id_map` 生成候选卡片、连线和完整 `editor_state`，新连线写入 `link_views`。
  3. 调用 `apply`。
  4. 采用返回的画布与文稿版本。
  5. 恢复自动保存。

  候选联系端点可以是文稿、新建框（`created`）、精确锚点（`anchor`）或场景实例（`scene`）。预览连线与隔离副本按同一规则定位：
  - 文稿取卡片，没有卡片时取该文稿的片段卡片。
  - 锚点取当前画布 `fragments` 中引用该锚点的片段卡片。
  - 场景端点直接使用 `object_id`。

  提案打开时，视口同时覆盖候选框和已在画布上的联系端点。撤销调用 `revert`。服务端返回依赖或版本冲突时保留当前内容并显示原因。拒绝不写入任何内容。
- **失败画布运行的恢复**：运行记录对失败的画布运行提供两项操作。
  - “从原输出恢复提案”调用 `POST /runs/{id}/recover-canvas-proposal`；成功后采用返回的运行，并打开提案。
  - JSON 内容本身无效时显示服务返回的具体错误，保留原输出与运行错误；此时可用“按原上下文重新生成”，以同一 `context_id` 发起新的结构化运行。
- **研究关系端点**：关系创建与修改支持类型化端点。
  - 文稿：`{type:'document', id}`。
  - 精确锚点：`{type:'anchor', id}`，对应片段卡片。
  - 冻结场景中的自由想法：`{type:'canvas_object', context_id, canvas_id, instance_id}`，对应便笺、文字、形状。

  对一条连线执行“研究这个联系”时，前端按两端实例确定端点类型：
  - 两端都是文稿时沿用 `source_id`/`target_id`。
  - 含自由想法时，先保存画布，再以 `mode=relation` 冻结两端与连线的场景，然后用 `canvas_object` 引用其中的实例。

  关系标题、学科桥端点与证据候选按 `source_ref`/`target_ref` 解析：片段显示原文与版本；想法显示冻结时的文字，所需场景按需读取；旧 `source_id`/`target_id` 只作为不透明标识使用。画布按类型化端点补齐或恢复关系连线。
- **学科桥**：五种状态为启发、候选、有支持、已确立、被反驳；历史值 `verified` 显示为已确立。
  - `claim.missing_proof`（尚缺论证）和 `claim.next_validation`（下一步验证方法）作为研究内容编辑，随 `PATCH /relations/{id}` 保存。候选状态且记录了证据缺口时，卡片顶部显示“证据缺口 · 保持候选”，关系列表显示“证据缺口”标记。AI 候选联系的缺口与验证方法在提案面板中显示。
  - 状态升级通过 `POST /relations/{id}/review` 提交：带版本的锚点或整篇证据（支持/推导/反例）、判断依据，以及人工确认。
  - 编辑已有确认记录的关系时携带 `expected_claim_revision`。服务端标记 `review_required` 后显示“待复核”及上次确认的依据和证据版本，原判断保留。
- **打开工作区时的画布**：优先打开浏览器保存的 `rc:canvas:<workspace_id>`。该值缺失或指向已删除画布时，打开工作区画布列表的首项；服务按 `updated_at,id` 升序返回，首项是最久未更新的画布。
- **讨论**：预览上下文与发送使用同一 `context_id`；生成结果以 SSE 流式显示，回答按 Markdown（含表格与公式）渲染并保存为讨论文稿。讨论脉络按上下文关系组织，合并讨论挂在最近的直接分支下。

未实测：

### 2026-10-24 基础流程

2026-10-24 在真实后端（模型 `cc/gemini-3.8-flash-high`）上用 Playwright 驱动 Chrome 完成以下操作，截图见流程图：

- 后端未连接与重连；工作区创建与切换；PDF 导入；文稿输入与行内/块级公式；画布放置、拖动、缩放、框、卡片内编辑。
- 选段讨论、上下文预览、流式生成；分叉两个分支、并排比较、合并讨论及其上下文。
